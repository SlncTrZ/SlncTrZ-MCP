# SlncTrZ-MCP v0.3.2

Date: 2026-09-12

## User-visible changes

- Hardens MCP provider recovery so a stale legacy Streamable HTTP session no longer requires Owner Console `Sync` to restore the provider.
- Keeps failed provider calls fail-safe: the request that discovers the stale session fails once and is never replayed automatically; a later caller may retry explicitly after recovery.
- Extends Owner Console sessions from a fixed 15-minute window to a 3-hour sliding idle timeout with a 12-hour absolute cap.
- Simplifies `/owner` Overview to Commands and MCP operational health, moves runtime/build detail into collapsed Advanced, and aligns panel styling with the existing restrained cyan/violet sign-in visual language.
- Sign out now revokes only the current Owner session instead of all concurrently active Owner sessions.

## Provider reliability changes

- A legacy Streamable HTTP `404` received while an MCP session is attached is classified internally as an invalid session, clears stale session state, and triggers a fresh provider-local handshake.
- Restart attempts are bounded per recovery incident rather than accumulated for the entire runtime generation. A successful recovery therefore restores the full restart budget for future independent incidents.
- A provider that is temporarily unavailable during gateway startup receives bounded background recovery instead of remaining failed until an Owner/policy reload.
- Automatic recovery remains isolated to the affected provider; regression coverage verifies that recovery of provider A does not restart provider B.
- Process-local counters record invalid-session observations plus recovery success/failure without provider labels, credentials, tool arguments, or provider result content.

## Security-relevant changes

- Provider recovery does not replay the failed tool call. This prevents a reconnect from duplicating write/execute side effects when the gateway cannot prove whether an upstream operation was committed.
- Ordinary upstream `5xx`, protocol errors, and other provider failures are not reclassified as a successful stale-session path.
- Owner cookies retain `Secure` when served over HTTPS, `HttpOnly`, `SameSite=Strict`, and `Path=/owner`; sliding renewal never extends a session beyond the 12-hour absolute deadline.
- Expired Owner session records are pruned during normal authentication activity.

## Migration / restart / reauthorization

- No managed-state schema migration is required.
- The supported update path preserves Paths, Commands, MCP provider definitions, provider credentials, Owner Passphrase, OAuth state, audit history, usage history, and global harness state.
- Updating/restarting the gateway invalidates process-local Owner sessions, coding-context receipts, and managed task state as documented; sign in/bootstrap again afterward.
- No OAuth reauthorization is required solely by this release. Clients that cache tool metadata may still need fresh discovery after update.

## Supported / prebuilt targets

- Linux x64 standalone and User Install remain public release targets.
- Windows x64 standalone and User Install remain public release targets through Git Bash bootstrap plus the native Windows runtime.
- Linux System Install remains implemented but requires separate clean-systemd-host evidence for a verified support claim.
- Windows System Install/service mode is not supported.
- Source runtime remains Node.js `>=22.13.0 <25`.

## Known limitations

- Automatic provider fault recovery is provider-local, but Owner-driven provider configuration mutations (`Add`, `Enable/Disable`, `Sync`, credential activation) still activate through a policy/runtime generation reload. With multiple configured providers, such an explicit Owner mutation may re-handshake providers that were not edited. Generation-local configuration activation remains a future scalability optimization.
- The gateway deliberately does not automatically retry the tool call that observed provider failure; callers decide whether an explicit retry is semantically safe.
- Owner sessions, context receipts, and managed tasks remain process-local and do not survive a gateway restart.
- Windows release binaries retain the signing/trust limitations documented for the current 0.3.x line.

## Rollback

- Normal rollback continues to use verified immutable release metadata and preserves customer state.
- Rolling back to v0.3.1 restores the older provider recovery/session behavior; configuration and stored state remain compatible because v0.3.2 introduces no managed-state schema change.
