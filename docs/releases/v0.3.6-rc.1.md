# SlncTrZ-MCP v0.3.6-rc.1

Date: 2026-09-26

Prerelease candidate for the v0.3.6 signed-release line. Promotes to stable only after the automated signed-release gates plus live acceptance and final candidate audit succeed.

## User-visible changes

- Carries the full post-v0.3.5 Master Audit hardening set: safer Owner OAuth retry/failure budgets, durable token-exchange diagnostics, failure-safe authorization-code redemption, durable-before-visible DCR, ingress cancellation/abort classification, managed-task terminal audit, bounded recurrent provider recovery, degraded Usage health, and publisher-authenticated release manifests.
- Adds the 2026-09-25 follow-up Opencode hardening: loopback control-plane Owner failure limiting, durable-first DCR revocation, MCP runtime-lease cleanup on handler-construction failure, bounded Usage tool identifiers, rollback target re-verification, one overall manifest/signature retrieval deadline, and ref-counted Debate wait signals.
- Release bundles include `manifest.json.sig` for Ed25519 publisher authentication. This candidate is the first published candidate carrying the signing-enabled trust root.

## Behavior

- All hardening after the exact `v0.3.5` tag is documented in this release line and in the `0.3.6-rc.1` section of `CHANGELOG.md`; the historical v0.3.5 release notes are intentionally not backfilled.
- Version-bearing identity for this candidate is `0.3.6-rc.1` across `package.json`, standalone `--version`/`--build-info`, manifest version, tag, and release assets.

## Security-relevant changes

- Setup/update verifies the Ed25519 signature over the exact canonical `manifest.json` bytes before parsing it; artifact size and SHA-256 verification remain required after manifest authentication.
- Signing custody is not fully accepted: the 2026-09-26 GitHub configuration check confirmed the `release-signing` Environment, tag rule `v*`, a required reviewer, and administrator bypass disabled, but `prevent_self_review` was `false`. This does not satisfy the release-signing custody gate in `docs/RELEASE_ACCEPTANCE.md`. Independent verification of Environment-only private-key custody and absence of duplicate secrets remains outstanding.
- The aggregate signing job remains tag-only, verifies the tag commit is on `origin/main` history, and cannot obtain the production private key on non-tag dispatch.
- OAuth durable state stores token hashes/metadata rather than plaintext bearer or refresh credentials; pending authorization transactions/codes remain process-local.

## Migration / restart / reauthorization

- Existing v0.3.5 managed state remains valid; `audit.sqlite3` receives an additive migration for bounded auth reason/operation fields only.
- Pending authorization transactions/codes and managed Task Runtime state remain process-local and reset on restart; acknowledged OAuth grants/token families remain durable.
- This candidate carries the signing-enabled trust root: later setup/update manifest retrieval fails closed unless the configured publisher signature verifies.

## Verification status

- The [standalone release workflow](https://github.com/SlncTrZ/SlncTrZ-MCP/actions/runs/36233772456) passed on candidate commit `3fb91e9`: Linux Node 22/24 and Windows Node 24 quality gates, both native builds and identity checks, signed-bundle publication, both clean User Install gates, and installed `/usage` browser acceptance. Stable promotion was skipped for the RC tag.
- The separate [main CI workflow](https://github.com/SlncTrZ/SlncTrZ-MCP/actions/runs/36233744863) failed at the Windows SEA build because that workflow did not supply the now-required release-signing public key. Release-workflow success does not make that independent CI run green; the follow-up CI fix requires its own verification.
- Live ChatGPT/tunnel OAuth acceptance, deployed durable failed-token evidence, release-signing custody acceptance, and final exact-candidate audit remain promotion gates.

## Supported / prebuilt targets

- Linux x64 and Windows x64 standalone plus clean public User Install, subject to the release workflow gates.
- Source runtime remains Node.js `>=22.13.0 <25`.

## Known limitations

- Prerelease: do not treat as stable until promoted.
- Deleted debates cannot be recovered.
- Real ChatGPT/live-tunnel OAuth acceptance remains a promotion gate.
- The `release-signing` Environment must be corrected to prevent self-review and independently re-verified before stable promotion.

## Rollback

- Normal rollback uses verified immutable release metadata and preserves managed state.
- Rolling back to v0.3.5 preserves compatible data but removes all post-v0.3.5 audit/signing hardening carried by this candidate; debates deleted while on this candidate stay deleted.
