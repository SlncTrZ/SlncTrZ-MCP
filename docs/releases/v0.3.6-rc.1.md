# SlncTrZ-MCP v0.3.6-rc.1

Date: 2026-09-26

Prerelease candidate for the v0.3.6 signed-release line. Promotes to stable only after the automated signed-release gates plus live acceptance and final candidate audit succeed.

## User-visible changes

- Same product surface as v0.3.5 plus the 2026-09-25 follow-up Opencode audit hardening: control-plane Owner failure budget, durable-first DCR revocation, MCP lease release on handler-construction failure, bounded Usage tool identifiers, re-hashed rollback targets, bounded manifest/signature retrieval deadline, and ref-counted Debate wait signals.
- Release bundles include `manifest.json.sig` for Ed25519 publisher authentication. This candidate is the first built after the production `release-signing` GitHub Environment was configured.

## Behavior

- No product behavior change versus `fix/release-0.3.5` HEAD beyond the hardening already documented in `docs/releases/v0.3.5.md` and `CHANGELOG.md` for 0.3.5.
- Version-bearing identity for this candidate is `0.3.6-rc.1` across `package.json`, standalone `--version`/`--build-info`, manifest version, tag, and release assets.

## Security-relevant changes

- Signing custody: `release-signing` Environment pre-created with tag-only rule `refs/tags/v*`, required reviewer, prevent self-review, administrator bypass disabled; signing private key exists only as an Environment secret with no repository-level duplicate; public key published as an Environment variable and verified to match before first use.
- The aggregate signing job remains tag-only, verifies the tag commit is on `origin/main` history, and cannot obtain the production private key on non-tag dispatch.

## Migration / restart / reauthorization

- Same as v0.3.5: existing managed state remains valid; `audit.sqlite3` receives an additive migration only; pending transactions/codes and Task Runtime state remain process-local.
- This candidate carries the signing-enabled trust root: setup/update manifest retrieval verifies the Ed25519 publisher signature before parsing.

## Verification status

- Source gates on the exact candidate commit: `npm run docs:check` and targeted unit suites green before tagging; full `npm run check` evidence recorded at tag time by CI (Linux Node 22/24, Windows Node 24).
- Live acceptance and final candidate audit run against this exact prerelease before any stable promotion.

## Supported / prebuilt targets

- Linux x64 and Windows x64 standalone plus clean public User Install, subject to the release workflow gates.
- Source runtime remains Node.js `>=22.13.0 <25`.

## Known limitations

- Prerelease: do not treat as stable until promoted. Deleted debates cannot be recovered. Real ChatGPT/live-tunnel OAuth acceptance remains a promotion gate.

## Rollback

- Normal rollback uses verified immutable release metadata and preserves managed state. Rolling back to v0.3.5 preserves data; debates deleted while on this candidate stay deleted.
