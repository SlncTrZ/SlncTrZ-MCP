# SlncTrZ-MCP v0.4.4

Date: 2026-10-10

This release brings the optional CyberBrain Prediction Seam into the signed standalone runtime, replacing the need for a separate source-bundle entrypoint.

## User-visible changes

- Opt in with `SLNCTRZ_PREDICTION_SEAM_ENABLED=true` in the gateway service environment.
- For non-read tools on other providers, record a transport-level expectation before dispatch and resolve the outcome afterward.
- Successful transport is confirmed; provider errors contradict the expectation; timeout/cancellation is indeterminate.
- Recording and resolution each have a one-second deadline. Backend failures do not replace the provider result; late or failed recording skips resolution.
- The corrected Chromium acceptance harness from v0.4.3 recovery is included in the release source. Gateway-only bootstrap exemption, actual provider structuredContent and the v0.4.3 dashboard are retained.

## Security-relevant changes

- The feature is disabled by default and enabled only through owner-controlled runtime configuration.
- The seam is gateway-owned telemetry using the configured `cyberbrain` provider, not an additional client tool grant. Main provider dispatch retains its authorization and Full/Gateway-only boundaries.
- Caller tool arguments and provider output are not copied into predictions; only tool/risk, client/request identifiers, timestamps and transport outcome are recorded.
- CyberBrain tools and read-only tools are excluded, preventing recursion and read noise.
- Mandatory Ed25519 publisher signature verification precedes artifact SHA-256 and size checks. Windows Authenticode signing is not claimed.

## Migration / restart / reauthorization

- Back up state/config coherently before upgrading, then restart and refresh MCP tool discovery.
- OAuth schema remains v3; existing grants and credentials are preserved. Full context receipts, Owner sessions and managed tasks are process-local and must be recreated after restart.
- For pre-v0.3.6 installations, `audit.sqlite3` receives an additive migration for bounded authorization reason/operation fields.
- A service previously running a local patch must switch its ExecStart to the installed launcher to use the signed release. Keep any required `NODE_EXTRA_CA_CERTS` and the seam flag in the service environment; neither depends on the patch entrypoint.
- No reauthorization is required solely for this feature.

## Supported / prebuilt targets

- Linux x64 with User/System install paths; hosted public acceptance covers User Install.
- Windows x64 User Install; Windows System Install/service remains unsupported.
- Source gates exercise Linux Node 22/24 and Windows Node 24; native identity, signed manifests, public installs and installed Chromium gate stable publication.

## Known limitations

- Predictions describe transport success, not correctness of the tool's domain-specific work.
- Learning is best-effort: unavailable backends, deadline expiry, shutdown or lost responses may leave missing/unresolved predictions. A timed-out backend may have persisted a record before cancellation.
- The optional seam can add up to two seconds total latency per eligible provider call.
- A ready CyberBrain provider exposing prediction_record/prediction_resolve is required; shared provider credentials may attribute all seam records to one trusted backend identity.
- Named real-client OAuth and deployment-specific service/keyring acceptance require separate live evidence.

## Rollback

- Disable the seam flag to stop new learning while retaining normal provider calls.
- Rolling the launcher back to v0.4.3 removes the seam without changing OAuth schema. Retain required CA configuration.
- Restore coherent pre-migration state/config when rolling back to pre-v3 binaries.
