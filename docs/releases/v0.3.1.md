# SlncTrZ-MCP v0.3.1

Date: 2026-09-11

## User-visible changes

**Canonical product positioning:** Owner-controlled access from Web AI to your Linux or Windows machine — files, commands, Agent Skills, tasks, and MCP servers through one gateway.

- Adds `/usage`, a read-only owner dashboard for measured MCP traffic, per-tool estimated context, progressive Agent Skill savings, and custom-price cost estimates.
- Raises the bounded `SKILL.md` size from 128 KiB to 256 KiB so substantial Agent Skills can be used directly while remaining progressively disclosed.
- Reworks the public README and User Guide around the questions an evaluator/operator actually has: why the project exists, what it gives you, how to install it, what authority it has, what `/usage` measures, and where the current adoption gaps are.
- Keeps exact model/provider billing outside the product claim. The dashboard measures the gateway boundary and labels token/dollar values as estimates.

## Security-relevant changes

- Usage telemetry is a new independent observability path with its own `<stateRoot>/usage.sqlite3`; it does not extend or replace `audit.sqlite3`.
- The usage schema excludes prompts, MCP request bodies, tool arguments, paths, file contents, command output, provider payloads, credentials, bearer tokens, and context receipts.
- Telemetry is non-authoritative and fail-open. Estimator, queue, SQLite, or dashboard failure must not deny, authorize, replay, or fail an otherwise valid MCP operation.
- Usage data APIs stay under `/owner/api/usage/*` and require the existing Owner session. `/usage` introduces no new credential and the Owner cookie remains scoped to `/owner`.
- Internal automated security evidence is not presented as an independent security certification. External review remains valuable and explicitly welcome.

## Migration / restart / reauthorization

- The supported update path preserves policy, Owner Passphrase, OAuth/provider configuration, harness state, and existing audit history.
- `usage.sqlite3` is created on first v0.3.1 startup when the state root is writable. There is no usage-history migration from v0.3.0 because the feature did not exist there.
- Existing context receipts and managed task state remain process-local and are renewed/lost on restart exactly as before.
- No OAuth reauthorization is required solely by the usage feature, but clients may still need fresh tool discovery after upgrade when their host caches the MCP catalog.

## Supported / prebuilt targets

- The intended release targets remain Linux x64 and Windows x64 standalone/User Install, subject to the full release acceptance gates for the published v0.3.1 artifacts.
- Linux System Install remains implemented and requires its own clean-host systemd evidence before a verified support claim.
- Windows System Install/service mode is not supported.
- Source runtime remains Node.js `>=22.13.0 <25`.

## Known limitations

- `utf8-bytes-v1` is a model-neutral estimate, not the tokenizer or billing meter of OpenAI, Anthropic, Google, xAI, or another provider.
- `/usage` does not see the user's full webchat prompt, platform-owned system/developer context, hidden reasoning, or the model's normal chat answer.
- Progressive-disclosure savings use a defined eager-load baseline: bootstrap context plus all active `SKILL.md` bodies. Referenced resources remain normal measured gateway traffic rather than hypothetical eager context.
- Project/community adoption is still limited. Internal architecture/test maturity should not be confused with broad third-party deployment evidence or independent audit.
- Windows release binaries remain subject to the signing/trust limitations documented for the current 0.3.x line.

## Rollback

- Rolling back to v0.3.0 leaves `usage.sqlite3` as preserved state; the older runtime does not consume it.
- The global harness remains owner state. A skill larger than the older release's 128 KiB bound may become undiscoverable after rollback even though the file remains intact.
- Normal rollback continues to use verified immutable release metadata and does not delete customer state.

See `CHANGELOG.md`, `README.md`, `docs/USER_GUIDE.md`, `docs/THREAT_MODEL.md`, and ADR-028 for the complete v0.3.1 behavior and claim boundaries.
