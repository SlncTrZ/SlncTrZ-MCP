# SlncTrZ-MCP v0.3.6

Date: 2026-09-29

Stable release of the v0.3.6 line. This release includes the hardening recorded in the rc.1 through rc.4 notes and the final Owner UI and Debate wait corrections below.

## User-visible changes

- The Owner Console can delete one OAuth connection (grant) after confirmation. This immediately revokes that grant without affecting sibling connections.
- The Debate history page can delete a finished, stopped, paused, or waiting debate after confirmation. Active debates must be stopped first.
- `debate.wait` accepts a maximum of 20 seconds for one HTTP call. To wait longer, repeat calls with the last seen sequence until a caller-selected overall deadline; a request timeout does not end the Debate turn.

## Security-relevant changes

- The Connections Delete button no longer mistakes its Apply button for the browser confirmation function.
- Debate deletion sends the Owner session's CSRF token even though its DELETE request has no body. The server's CSRF requirement remains enforced.
- The MCP schema, service bound, and tool description agree on the 20-second Debate wait limit.
- This line also includes the rc.4 installed-binary re-verification, bounded pending OAuth authorization allocation, and serialized installation metadata writes.
- OAuth grants and token families remain durable in private SQLite, with token hashes rather than plaintext token values. Existing v0.3.6 auth diagnostics retain bounded reason and operation metadata.

## Migration / restart / reauthorization

- No new managed-state migration is introduced after rc.4. Across the v0.3.6 line, `audit.sqlite3` receives an additive migration for bounded auth reason/operation fields. Existing compatible 0.3.x state, Paths, Commands, provider settings, Owner Passphrase, OAuth grants, and Debate data are preserved by the normal update path.
- In-memory context receipts, pending OAuth transactions, Owner sessions, and managed Runner tasks are recreated after a gateway restart.

## Supported / prebuilt targets

- Linux x64 and Windows x64 standalone/User Install are the public targets. Windows System Install is not supported. Linux System Install requires separate disposable-systemd-host evidence for a verified end-user claim.

## Verification

- The source quality and documentation gates passed on the final-fix commit in an isolated Linux Node 24 checkout; focused Owner UI, Debate and MCP tests passed.
- Official exact-tag CI, signed publication, clean public Linux/Windows User Install, and installed `/usage` browser acceptance are required before this release is called stable. Record their run IDs and exact SHA in the release evidence.

## Known limitations

- Debate deletion is permanent; there is no trash or undo.
- A 20-second `debate.wait` does not keep a client running across closed chat sessions. Pickup and response deadlines are separate from the HTTP wait.
- Windows Authenticode signing is not claimed. The updater verifies the Ed25519 publisher signature on the release manifest.

## Rollback

Normal rollback uses verified immutable release metadata and preserves compatible managed state. A deleted debate cannot be restored by rolling back.
