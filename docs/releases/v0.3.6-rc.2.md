# SlncTrZ-MCP v0.3.6-rc.2

Date: 2026-09-27

Prerelease correction candidate for the v0.3.6 signed-release line. It supersedes v0.3.6-rc.1 for promotion evidence and must pass the automated signed-release gates plus live acceptance and final exact-candidate audit before stable promotion.

## User-visible changes

- Preserves the full v0.3.6 hardening set from rc.1.
- Corrects browser OAuth approval/retry behavior so same-origin form submissions retain a normal Origin header instead of becoming `Origin: null`.
- Corrects Windows source CI SEA verification and release-history/documentation drift found after rc.1.

## Behavior

- Authorization and retry HTML uses `Referrer-Policy: same-origin`; successful OAuth callback redirects remain `no-referrer`.
- Explicit `Origin: null` and untrusted cross-origin requests remain rejected. The Origin allowlist is not broadened.
- Version-bearing identity for this candidate is `0.3.6-rc.2` across package metadata, standalone identity, manifest version, tag, and release assets.

## Security-relevant changes

- Host/Origin validation remains ahead of Owner Console, OAuth, and MCP dispatch.
- Source CI generates a disposable Ed25519 verification key for non-published Windows SEA verification; it does not use or establish production signing trust.
- Official manifest signing still requires the protected `release-signing` Environment and its production private key; the resulting publisher signature authenticates the exact canonical manifest bytes before parsing.
- Signing custody remains a promotion gate until self-review prevention and private-key custody are independently verified.

## Migration / restart / reauthorization

- Existing v0.3.5 and rc.1 managed state remains valid; `audit.sqlite3` receives an additive migration for bounded auth reason/operation fields only.
- Pending authorization transactions/codes and managed Task Runtime state remain process-local and reset on restart; acknowledged OAuth grants/token families remain durable.
- No new state migration is introduced by the rc.2 OAuth/CI correction itself.

## Verification status

- Pre-candidate Windows Node 24 quality gate passed on the correction wave: 95 test files passed, 1 skipped; 660 tests passed, 23 skipped.
- `npm audit --audit-level=moderate` reported zero vulnerabilities on the correction wave.
- Hosted CI, signed-release publication/clean-install acceptance, live ChatGPT OAuth acceptance, deployed durable failed-token evidence, release-signing custody acceptance, and final exact-candidate audit must be re-run on the exact rc.2 candidate SHA. Earlier rc.1 evidence does not substitute for rc.2 evidence.

## Supported / prebuilt targets

- Linux x64 and Windows x64 standalone plus clean public User Install, subject to the release workflow gates.
- Source runtime remains Node.js `>=22.13.0 <25`.

## Known limitations

- Prerelease: do not treat as stable until all promotion gates pass.
- Deleted debates cannot be recovered.
- Real ChatGPT/live-tunnel OAuth acceptance remains a promotion gate.
- The `release-signing` Environment must satisfy the documented custody contract before stable promotion.

## Rollback

- Normal rollback uses verified immutable release metadata and preserves managed state.
- Rolling back to v0.3.5 preserves compatible data but removes post-v0.3.5 hardening; debates deleted while on this candidate stay deleted.
