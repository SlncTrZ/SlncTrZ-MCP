# SlncTrZ-MCP v0.3.0

Date: 2026-09-09

## User-visible changes

- Adds the coding-harness surface: automatic global `AGENTS.md` discovery, optional authorized project instructions, `context.bootstrap` receipts, and progressive Agent Skills through `skills.read`.
- Bundles starter code-review and debug/test skills while keeping owner-managed global harness state outside immutable release directories.
- Carries forward bounded PNG/JPEG reads with explicit client display guidance.
- Keeps the existing MCP capability model: the harness supplies instructions and context, but never grants filesystem, process, provider, or policy authority by itself.

## Security-relevant changes

- Rollback now fails closed before activation when the target release cannot parse configured runtime keys such as `SLNCTRZ_HARNESS_ROOT`.
- Filesystem containment uses native relative-path semantics, including filesystem-root handling, instead of separator-prefixed string matching.
- Stale coding-context receipts are reclaimed when global/project instructions or policy generations change, without weakening stale-context rejection.
- Windows Node 24 source quality is now a release gate alongside Linux Node 22/24.
- Harness discovery performance was improved without caching completed context snapshots; current instruction/skill content is still re-read and hashed for freshness.

## Migration / restart / reauthorization

- After upgrading from 0.2.x, refresh the MCP tool catalog and call `context.bootstrap` before ordinary coding work.
- Context receipts are in-memory, expire after four hours, and must be renewed after gateway restart or relevant instruction/policy changes.
- Existing OAuth clients, Owner Passphrase, policy, command catalog, provider configuration, and user state are preserved by the supported update path.
- No blanket OAuth reauthorization is required solely because of the 0.3.0 upgrade.
- A custom `SLNCTRZ_HARNESS_ROOT` is a 0.3.0-only runtime setting; remove or adjust it before rolling back to a release that predates that key.

## Supported / prebuilt targets

- Linux x64 SEA and User Install: release-verified by clean public GitHub Release installation.
- Windows x64 SEA and User Install: release-verified by clean public Git Bash bootstrap plus native Windows runtime acceptance.
- Source runtime: Node.js `>=22.13.0 <25`; release CI covers Node 22 and 24 on Linux and Node 24 on Windows.
- Linux System Install is implemented, but this release does not claim clean-host systemd verification.
- Windows System Install/service mode is not supported.

## Known limitations

- Windows v0.3.x binaries are not Authenticode-signed; official GitHub Release origin and published SHA-256 checksums remain the release trust mechanism.
- Named ChatGPT/Claude connection flows are documented, but this release does not claim real-client verification unless separate release evidence records it.
- Gemini Spark still requires the documented one-time manual new-tab redirect workaround after Owner approval.
- Coding-context receipts are process-local rather than durable; restart requires a fresh bootstrap.

## Rollback

- The public `0.2.10 -> 0.3.0 -> 0.2.10` User Install lifecycle is verified with Owner Passphrase, policy, command catalog, and client configuration preserved.
- Rollback is intentionally blocked before activation when the current configuration contains a runtime key unsupported by the target release.
- Default uninstall removes program files while preserving state/config unless an explicit destructive option is requested.

See `CHANGELOG.md`, `RELEASE.md`, `docs/HARNESS.md`, and `docs/CODING_AGENTS.md` for detailed behavior and integration guidance.
