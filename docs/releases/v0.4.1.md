# SlncTrZ-MCP v0.4.1

Date: 2026-10-08

This release line includes the previously unpromoted v0.4.0 feature set and the follow-up
release corrections. The existing v0.4.0 tag is retained unchanged.

## User-visible changes

- Select Full or Gateway-only during initial OAuth consent. New Gateway-only grants persist
  until revocation with short-lived access tokens and rotating single-use refresh tokens.
- Owner connection controls enforce immutable consent ceilings; Usage charts show numeric
  gateway traffic estimates.
- Correct operational guidance for launcher/systemd restart, coherent backup, uninstall
  retention, provider discovery and additional repository skills.
- Fresh installed defaults contain code-review/debug-and-test. Other repository skills require
  explicit project discovery or owner installation.

## Security-relevant changes

- Windows deferred self-removal resolves absolute system CMD/PowerShell paths and requires
  a bounded ready/go startup handshake. Startup failure preserves managed files.
- Native smoke tests quoted paths and Windows shell PATH/install cwd alongside all retention modes.
- Benchmark processes use private temporary state, never the account's live policy/providers.
  Cleanup covers normal completion and failure; Windows system environment is retained.
- Lock dev/build source-map-js to 1.2.2 for GHSA-68fv-2mgg-jv7q.
- Retain mandatory Ed25519 publisher signature verification on exact manifest bytes, followed
  by artifact SHA-256/size verification. Windows Authenticode signing is not claimed.
- The lifecycle ledger remains an unwired foundation; it does not control CAD or make tasks durable.

## Migration / restart / reauthorization

- Stop/quiesce the gateway and back up state/config together before upgrade.
- OAuth schema v1/v2 migrates to v3. Existing grants retain finite lifetime, profile and label
  semantics. Fresh Gateway-only consent adopts the durable policy.
- Restart after update; refresh discovery and recreate process-local context receipts, tasks,
  Owner sessions and pending authorization transactions.
- For pre-v0.3.6 installations, `audit.sqlite3` receives an additive migration for bounded
  authorization reason/operation fields.

## Supported / prebuilt targets

- Linux x64 and Windows x64 standalone User Install.
- Source: Linux Node 22/24, Windows Node 24; package runtime contract >=22.13.0 <25.
- Windows System Install is unsupported; Linux System Install claims require separate
  disposable-systemd-host evidence.
- Native SEA includes Node; no source checkout/npm/system Node is required to run it.

## Verification

[QA report](../../QA_QC_REPORT_v0.4.1.md) records the final local review and test evidence.
Published release status and workflow results determine public acceptance.

The release workflow requires source/native gates, exact commit/version/hash identity,
protected manifest signing, public Linux/Windows clean User Install and installed Usage
browser acceptance before stable promotion. Local disposable-key binaries are unpublished tests.

## Known limitations

- Independent signing custody and named real-client acceptance are separate claims.
- Usage estimates gateway traffic; it does not measure provider billing or platform allowance.
- Durable authorization does not guarantee network/provider availability; reused refresh tokens fail.
- Runner/Coordinator and context receipts remain in-memory. The ledger has no live controller wiring.
- Image transport success alone does not establish model perception or user attachment display.
- The benchmark JSON field authenticatedCorePing measures the MCP protocol ping method,
  not a tools/call invocation of core.ping.

## Rollback

Pre-v3 binaries reject OAuth schema v3. Rolling back to v0.3.7 requires restoring the coherent
pre-migration state/config backup while stopped; binary-only rollback is insufficient.
Restoring a backup loses later OAuth changes. Do not silently downgrade the live schema.
Normal uninstall preserves state/config by default, but that does not make older schemas compatible.
