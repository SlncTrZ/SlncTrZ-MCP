# SlncTrZ-MCP v0.3.7

Date: 2026-10-05

## User-visible changes

- The site root `/` now opens the Owner homepage. Existing `/owner` links remain compatible.
- Owner, Debate and Usage share a modern dashboard sidebar, responsive navigation and updated layouts.
- Dashboard transitions and the startup logo animation support reduced motion; the intro can be skipped or replayed.

## Security-relevant changes

- Update locked Hono and brace-expansion dependencies to patched compatible versions.
- MCP HTTP providers recover a rejected remote session with one bounded retry. A healthy container with a stale session can reconnect without remaining unavailable.
- Invalid MCP tool arguments do not restart a healthy provider.
- Debate selection ignores stale asynchronous responses. Connections Apply reports API failures.
- Owner API authentication, CSRF protection and Host/Origin validation remain enforced. The OAuth `/auth` flow is unchanged.

## Migration / restart / reauthorization

- No new managed-state migration is introduced. For upgrades from older 0.3.x state, the inherited v0.3.6 migration applies: `audit.sqlite3` receives an additive migration for bounded auth reason/operation fields. Compatible 0.3.x state, Paths, Commands, provider settings, Owner Passphrase, OAuth grants and Debate data are retained.
- In-memory contexts, pending OAuth transactions, Owner sessions and managed tasks are recreated after restart.
- Setup and status output now show the canonical root homepage URL.

## Supported / prebuilt targets

- Linux x64 and Windows x64 standalone/User Install are the public targets. Windows System Install is not supported. Linux System Install requires separate disposable-systemd-host evidence.

## Verification

- Publication requires the source CI gates on Node 22/24 and Windows, native standalone identity checks, signed manifest aggregation, exact-tag public Linux/Windows User Install and installed Usage browser acceptance.
- The release workflow publishes a prerelease candidate and promotes it to stable only after all public acceptance gates pass.
- Pipeline evidence does not certify every real AI client or independent signing custody.

## Known limitations

- The MCP retry addresses stale rejected sessions; provider connectivity, authorization and protocol errors can still make a provider unavailable.
- Usage remains an estimate of gateway-observed data, not provider billing or unobserved Webchat activity.
- Windows Authenticode signing is not claimed. Updates verify the Ed25519 publisher signature on the manifest.
- Debate deletion remains permanent.

## Rollback

Use verified immutable release metadata for the previous compatible release. Managed state is preserved by the normal rollback path; deleted debates cannot be restored by rollback.
