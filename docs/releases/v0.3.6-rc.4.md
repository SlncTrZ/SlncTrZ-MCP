# SlncTrZ-MCP v0.3.6-rc.4

Date: 2026-09-28

Post-rc.3 adversarial hardening candidate superseding rc.3 for promotion evidence.

## User-visible changes

- Carries the full v0.3.6 hardening and OAuth correction set.
- Existing-version updates now re-verify the installed binary before activation, so a substituted or tampered on-disk artifact is rejected instead of re-activated.
- Unfinished OAuth authorization transactions are now globally bounded, and installation metadata writes are serialized with UUID temp names so concurrent install/update cannot clobber the activation record.

## Security-relevant changes

- No Host/Origin allowlist relaxation.
- No signing-custody change.
- Official manifest signing still requires the protected `release-signing` Environment; the publisher signature authenticates the exact canonical manifest bytes before parsing.
- Update/activation integrity is strengthened: the previous installed release bytes are re-hashed and re-sized against immutable metadata before any rollback/activation, closing a substituted-artifact reactivation path.

## Migration / restart / reauthorization

- No new managed-state migration is introduced by rc.4; `audit.sqlite3` receives an additive migration inherited from the v0.3.6 release line for bounded auth reason/operation fields only.
- Existing v0.3.5/rc.1/rc.2/rc.3 compatible managed state remains valid.
- Pending authorization transactions/codes and managed Task Runtime state remain process-local and reset on restart; acknowledged OAuth grants/token families remain durable.

## Supported / prebuilt targets

- Linux x64 and Windows x64 standalone plus clean public User Install, subject to release gates.
- Source runtime remains Node.js `>=22.13.0 <25`.

- Real ChatGPT/live-tunnel OAuth acceptance and signing-custody acceptance remain open.
